Create a group on this node

This node keeps the group root, encrypted with a passphrase you choose and with ATLAS_SECRET_KEY. You also get a recovery file: keep it offline. Without it, losing this node means creating a new group.

Security notes

A stolen database without ATLAS_SECRET_KEY gives nothing. A stolen database (or backup) plus ATLAS_SECRET_KEY does not reveal the group root key directly, but it allows unthrottled offline guessing of the root passphrase at scrypt cost (N=2^17, r=8: about 128 MiB and 0.3-0.5 s per guess per core). A random 14-character passphrase resists that; a human-chosen phrase may not. Owners who keep backups together with the secret key should use the offline-root mode; this release does not offer it yet, so until then keep backups apart from ATLAS_SECRET_KEY and use a random root passphrase.

Recovery

How to recover the group root

Recovery runs on the command line of a member: atlas group root import --recovery-file F moves the root to that member (when the root node is lost); atlas group root succession --recovery-file F replaces a stolen root key with a recovery quorum (pending {{ group.genesis.body.policy.succession_delay_hours }} h); atlas group root succession-cancel cancels a succession that is not yours. Address and name changes are under "This node's address in the group" (or atlas group member-update). Offline root signing and box-key rotation are not available in this release.
