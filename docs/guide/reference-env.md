# Environment variables

_Generated by `tools/gen_docs.py` from the code. Do not edit by hand._

Every setting is read from an environment variable named `ATLAS_<NAME>` (or from a `.env` file). Settings marked **live** can also be changed at runtime in **Admin → Settings**; the environment value is then only the default.

## Node

| Variable | Default | Meaning |
| --- | --- | --- |
| `ATLAS_ROLE` | `local` | `authority` (the source of truth; publishes the signed change feed), `mirror` (replicates an authority) or `local` (a private node that caches providers and may replicate). |
| `ATLAS_DATABASE_URL` | `sqlite:///./atlas.db` | SQLAlchemy URL. `sqlite:///./atlas.db` for local nodes; `postgresql+psycopg://user:pw@host/db` for authorities (required in production). |
| `ATLAS_PUBLIC_URL` | `http://localhost:8000` | The address people use to reach this node. Used in emails, OIDC and links. Must be `https://` in production. |
| `ATLAS_ENVIRONMENT` | `dev` | `dev` shows API docs at `/docs` and relaxes production checks; `production` enforces HTTPS, PostgreSQL for authorities and an explicit initial administrator. |
| `ATLAS_NODE_KIND` | `auto` | Badge shown to visitors and peers: `auto` (follows the role), `official`, `community`, `mirror` or `local`. `official` is only a claim; people trust it by pinning your key. Editable in Admin → Settings. **live** |
| `ATLAS_NODE_OPERATOR` | — | Who runs this node. Editable in Admin → Settings. **live** |
| `ATLAS_INITIAL_ADMIN` | — | Username that becomes the website administrator when it registers. If unset, the first account to register is the administrator (production with open registration refuses to start without it). |
| `ATLAS_BOOTSTRAP_ADMIN_TOKEN` | — | 32+ random characters. Becomes an admin API token while set; removing it revokes it. Use it to create the first real tokens. |
| `ATLAS_SECRET_KEY` | — | Encrypts secrets stored in the database (the node signing key, peer tokens, OIDC client secrets, provider credentials entered in Admin → Integrations). Generate one with `atlas secret-key`. Losing it makes those secrets unreadable, and a backup's node identity unrecoverable. |
| `ATLAS_SECRET_KEY_PREVIOUS` | — | Comma-separated retired secrets that can still decrypt while you rotate `ATLAS_SECRET_KEY`. Run `atlas secrets rewrap`, then remove them. |
| `ATLAS_AUTO_MIGRATE` | — | Run database migrations on start. Default: on for SQLite, off otherwise. With several replicas set `false` and run `atlas migrate` as a job. |

## Federation

| Variable | Default | Meaning |
| --- | --- | --- |
| `ATLAS_UPSTREAM_URL` | — | Address of an upstream node to replicate from (simple single-upstream setups; more can be added under Admin → Peers). |
| `ATLAS_UPSTREAM_TOKEN` | — | API token (scopes `read`, `sync`) for `upstream_url`. |
| `ATLAS_TRUSTED_KEYS` | — | JSON object `{"<node id>": "<base64 public key>"}` of upstream nodes whose signed feed you trust. Required when `upstream_url` is set. Get the values from `atlas node` on the upstream. |
| `ATLAS_SYNC_INTERVAL_SECONDS` | `60` | How often to pull from peers (minimum 5). |
| `ATLAS_SYNC_BATCH_SIZE` | `500` | Feed entries fetched per request. |
| `ATLAS_SYNC_MAX_PARKED_BACKLOG` | `50000` | Entries a follower keeps downloading, verifying and relaying after the first entry it had to park (it needs a newer release). Above this it pauses downloading and reports `backlog_full`. |
| `ATLAS_MIN_FOLLOWER_PROTOCOL` | `1.0` | Lowest federation protocol a follower must speak to sync from this node (followers below it refuse). Default: the previous release's protocol. |
| `ATLAS_EMIT_PROTOCOL` | — | Newest federation protocol this node's own feed may use. Unset = `min_follower_protocol`. Raise it in Admin → Peers once every follower is upgraded. **live** |
| `ATLAS_FEDERATION_BRIDGE_RECORD_OBS` | `false` | Authority, emit protocol below 1.5: introduce a record its feed never signed (only provider data) with an ordinary observation of the source `atlas-record` (title and store ids), which every follower release applies. Off: such records reach followers only once the emit protocol is 1.5 (`record` entries). See [Changes waiting for their game](federation.md#changes-waiting-for-their-game). |
| `ATLAS_FEDERATION_INTRODUCE` | `referenced` | Authority: `referenced` introduces a record when a signed entry first names it; `all` also introduces every record made from provider data alone as it is created. |
| `ATLAS_FEDERATION_SNAPSHOT_FIELDS` | `['title', 'provider_ids']` | What a `record` (or bridge observation) carries besides the id and media type: a JSON list, a subset of `title` and `provider_ids`. |
| `ATLAS_SYNC_MAX_OPEN_FAILURES` | `10000` | Follower: open waiting and quarantined entries per upstream feed before it stops applying that feed and reports `backlog_full` (nothing is lost; the entries stay retained). |
| `ATLAS_SYNC_WAKE_BATCH` | `500` | Follower: waiting entries applied per transaction when their record arrives (1-5000); the retry pass of the same pull applies the rest. |
| `ATLAS_SYNC_ENRICH_FROM_OWN_PROVIDERS` | `false` | Follower (owner decision H56, off by default): when a `record` arrives, fetch the game from this node's own providers by the store ids it carries, so art and achievements arrive without redistribution. See [Changes waiting for their game](federation.md#changes-waiting-for-their-game). |
| `ATLAS_SYNC_ENRICH_PER_PEER_PER_HOUR` | `200` | Follower: at most this many own-provider fetches per upstream feed and hour (1-10000); the rest wait for the next hour. |
| `ATLAS_SYNC_MEDIA_PREFER_PEER` | `true` | Follower: fetch an image first from the peer whose feed delivered its artwork row (`/api/v2/sync/media/{sha256}`, hash checked), then from the original address. |
| `ATLAS_FEDERATION_MEDIA_UNKNOWN_LICENCE` | `false` | Whether `/api/v2/sync/media` hands a pinned peer the cached bytes of a curated image whose licence is unknown (none stated). Off: only `cc0` and owner uploads are served; peers fetch the rest from the original address. |
| `ATLAS_GROUP_VIEW_MAX_AGE_HOURS` | `24` | Node groups: how recent (hours, 1-168) a third member's view must be before delegated or privileged group actions. **live** |
| `ATLAS_GROUP_SYNC_INTERVAL` | `60` | Node groups: seconds between pulls of every member's state (30-86400). |
| `ATLAS_GROUP_PROFILE_SYNC` | `true` | Node groups: sync the preferences linked users chose over the private group channel. Off sends and applies nothing. **live** |
| `ATLAS_GROUP_PROFILE_FIELDS` | — | Node groups: space-separated preference names that may be synced; empty means every registry field the user agrees to. **live** |
| `ATLAS_GROUP_HOLD_TIMEOUT_DAYS` | `7` | Node groups: days a received preference waits for its missing history before it is applied with a review entry (1-90). **live** |
| `ATLAS_GROUP_MAX_DELEGATED_ROLE` | `none` | Node groups: the highest role a group grant may give here (`none`, `moderator`, `curator`, `admin`). The default `none` ignores every grant. **live** |
| `ATLAS_GROUP_FEDERATED_PRIVILEGE` | `deny` | Node groups: what a session opened through another node may do with local reviewer or administrator rights: `deny` (default), `local_mfa` (after this node's own second factor) or `allow`. **live** |
| `ATLAS_GROUP_TRUST_REMOTE_MFA` | `false` | Node groups: accept the other node's fresh (under 10 minutes) second factor in place of this node's own at a group sign-in. Off by default. **live** |
| `ATLAS_GROUP_DELEGATED_REQUIRES_MFA` | `true` | Node groups: rights from a group grant apply only after this node's own second factor in the session. On by default. **live** |
| `ATLAS_GROUP_AUTO_PROVISION` | `false` | Node groups: create a plain account (role user, no password, no email) at a group sign-in when none is linked here. Needs open registration. Off by default. **live** |
| `ATLAS_GROUP_SIGNIN` | `true` | Node groups: accept sign-ins confirmed by another member. Turning it off ends every session opened that way on the next request. **live** |
| `ATLAS_GROUP_SIGNIN_PUBLIC` | `false` | Node groups: show a sign-in button per member on the login page (this reveals group membership to visitors). Off by default. **live** |
| `ATLAS_GROUP_DENIED_ACCOUNTS` | — | Node groups: space-separated group account ids whose grants are ignored here. **live** |
| `ATLAS_INHERIT_SCHEMA` | `true` | Adopt the upstream authority's media types and custom fields (yours always take precedence). Editable in Admin → Settings. **live** |
| `ATLAS_OIDC_PROVIDER_ENABLED` | `false` | Let other nodes and the Tracking App sign users in with accounts on this node (OpenID Connect). Editable in Admin → Settings. **live** |

## Matching

| Variable | Default | Meaning |
| --- | --- | --- |
| `ATLAS_AUTO_MATCH_THRESHOLD` | `0.85` | Confidence (0.5–1.0) at or above which an incoming record is merged into an existing one automatically. Editable as a percentage in Admin → Settings. **live** |
| `ATLAS_REVIEW_THRESHOLD` | `0.6` | Confidence below the auto threshold but above this opens a possible-duplicate review. **live** |
| `ATLAS_SOURCE_TRUST` | `{'curator': 100, 'manual': 90, 'community': 85, 'igdb': 70, 'steam': 65, 'gog': 60, 'rawg': 50}` | JSON object of source name → trust weight used to choose between conflicting values (higher wins). Reserved names need the `curate` scope to submit. |
| `ATLAS_DEFAULT_TRUST` | `40` | Trust for sources not listed in `source_trust` (apps and plugins submitting data). |
| `ATLAS_REDISTRIBUTABLE_SOURCES` | `['community', 'curator', 'manual']` | Sources whose curated observations are published on the change feed. Provider data (Steam, IGDB…) is never federated. |
| `ATLAS_FIELD_SOURCE_PREFERENCE` | — | JSON object of field → list of sources, best first, for example `{"description": ["igdb", "steam"]}`. It reorders sources of the `provider` trust class only: it never lifts a provider above community or curator data (see Matching and provenance). |
| `ATLAS_SYNC_ORIGIN_CLASS_CAP` | — | JSON object of node id → highest trust class (`curator`, `publisher`, `community`, `provider`) its replicated observations may have. Unlisted nodes: a configured upstream authority (a node in `ATLAS_TRUSTED_KEYS` or under Admin → Peers) is `curator`, every other origin `provider`. |
| `ATLAS_REVIEW_DISMISS_DAYS` | `30` | Days a dismissed review pair stays closed: the same pair is not reopened within this window unless its evidence gets stronger. |
| `ATLAS_MATCH_DECISION_RETAIN_DAYS` | `180` | Days match decisions are kept. The newest decision of each source record and every decision an open review or a live merge refers to are always kept. |

## Limits

| Variable | Default | Meaning |
| --- | --- | --- |

A daily job then deletes every row that has a newer row for the same record; the newest row of each record is always kept. A client whose cursor is older than the oldest kept row gets `"reset": true` and must re-read. |

| `ATLAS_METRICS_DIR` | — | Several worker processes on one host: a private directory they share (writable by Atlas only). Each worker writes its counters there and any worker's `/metrics` reports all of them. Empty: every process reports only itself. |

| `ATLAS_MEDIA_CACHE_BATCH` | `10` | Images processed per background pass. |
| `ATLAS_MEDIA_ALLOWED_HOSTS` | — | If non-empty, only these hostnames may be downloaded from. Always public addresses only. A provider image not cached yet may also be redirected to these hosts by `/api/v2/artwork/{id}/image`. |

| `ATLAS_MEDIA_FETCH_DEADLINE_S` | `20` | Seconds one download may take in all, redirects and body included (5-60). |
| `ATLAS_MEDIA_HOST_CONCURRENCY` | `2` | Simultaneous downloads from one host, per process. |
| `ATLAS_MEDIA_HOST_RPM` | `60` | Downloads from one host per minute, per process. Over the limit an image waits a minute; it is not counted as a failure. |
| `ATLAS_MEDIA_MAX_FRAMES` | `300` | Most frames an animated image may have; the frames together may have at most 4 x `ATLAS_MEDIA_MAX_PIXELS` pixels. |
| `ATLAS_MEDIA_POLICY` | — | JSON overrides of the per-source media policy (C12 §12.5.5), for example `{"steam": {"fetch": "redirect"}}`. Fields: `fetch` (`proxy`, `redirect`, `none`), `federate`, `licence`, `attribution`, `redirect_hosts`. An unknown field or value stops the node at start-up. |
