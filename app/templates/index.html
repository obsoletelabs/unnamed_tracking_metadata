For applications

A small, usable REST API

All catalogue API reads and writes require a bearer API key.

Open interactive API docs ↗
GET
/api/v1/games?q=hollow

Search and list catalogue records, including schema fields, tags and provider IDs. Supports q, limit and offset.

API key
GET
/api/v1/games/{id}

Retrieve one record by its canonical ID, with tags, provider IDs and image references.

API key
GET
/api/v1/schemas

Fetch the schema contract so clients can discover supported custom fields.

API key
POST
/api/v1/games

Add a record with schema-validated custom fields, tags and registered external IDs.

API key
POST
/api/v1/games/{id}/images

Upload an image as multipart field file (PNG, JPEG, WebP or GIF; 5 MiB max).

API key
Example request
curl "http://localhost:8000/api/v1/games?q=hollow" \
  -H "Accept: application/json"

curl -X POST "http://localhost:8000/api/v1/games" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"Tunic","developer":"TUNIC Team","release_year":2022,"description":"An isometric adventure."}'

Catalogue reads now require a real bearer key; website search requires login. Rate limits, quotas, moderation and a formal migration system are still pending. Do not expose this prototype publicly yet.
